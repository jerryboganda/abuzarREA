## Round 4 (2026-11-25): silent sale-return save for a salesman without a user group
Found while save-testing with a dummy salesman: `w_multi_entry.wf_check_module_rights` (used by the Sale Return / Open Sale Return windows and their buffer window) returned -2 without any message when `f_getgroupcode(usercode)` is NULL/0 (user has no row in `UserGroups`), so Save silently did nothing.

| Library | Fix | Verification |
|---|---|---|
| components.pbd | **1 byte**: the `if ll_groupcode > 0` JUMPFALSE target 188 -> 106 (file offset 10577948, 0xBC -> 0x6A), so a group-less user falls into the existing "User Group Rights Validation: You do not have rights/permission for the concerned transaction. Please Contact administrator to the needfull" box and the function returns -1 (callers only test `< 0`). The old `return -2` is now unreachable. | Re-export of the patched library (62 objects): exactly 1 instruction differs from `recovered/pcode`; live: group-less dummy user -> message box, nothing saved (SRLedger unchanged); same draft with the group restored -> saved as SR 61607. Fiscalized=N on it (returns are not auto-fiscalized). |

Tools: `deploy\impl\tools\patch_components_rights_msg.py` (builds the patched file from the vendor `components.pbd`), `deploy\impl\tools\pcode_compare_tree.py` (diff of two p-code export trees); the patched file is also kept in `deploy\impl\staged\components.patched.pbd`. Rollback: close the app, copy `deploy\Application\_pbd_before_patch_20261123\components.pbd` back over `deploy\Application\components.pbd`.
The message is the app's existing "no rights" text; it does not say "no user group" specifically (a different string would not fit in place).
